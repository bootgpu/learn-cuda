## 摄氏转华氏

所有线程跑的是同一个 kernel。每个线程靠自己的 block 编号和线程编号，算出该处理哪个元素：

```cpp
int i = blockIdx.x * blockDim.x + threadIdx.x;
```

`blockIdx.x * blockDim.x` 是前面的 block 已经占掉的位置数，`threadIdx.x` 是这个线程在自己 block 里的位置。

`solve` 里的 block 数是向上取整的：`(n + threads - 1) / threads`，保证每个元素都有线程管。代价是最后一个 block 里可能有线程的 `i` 超出了数组末尾，这些线程不能碰内存，所以要用 `if (i < n)` 把计算包起来。

C 语言的一个细节：两个整数相除，`9 / 5` 等于 `1`，不是 `1.8`。写成 `celsius[i] * 9 / 5` 没问题：先算乘法，`celsius[i]` 是 float，结果也是 float。

## 一个线程算两个元素

本关在一种新的启动方式下，再练上面的下标公式。

一个线程算一个元素时，公式的意思是「前面的 block 占掉的位置，加上我在自己 block 里的位置」。换成本关的启动方式，把这两个问题重新问一遍：每个线程管两个元素了，前面每个 block 占掉多少个位置？一个线程的那两个元素，在自己 block 里从哪儿开始？线程算出第一个元素之后，第二个元素要单独跟 `n` 比一次：`n` 是奇数时，最后一个线程只有一个元素要算。

取相邻的两个元素不是唯一的分法。也可以让一个线程取数组前半段的一个、后半段的一个。两种写法本关都能过；到「kernel 性能调优」一章讲合并访存时，再比较它们在速度上的差别。
